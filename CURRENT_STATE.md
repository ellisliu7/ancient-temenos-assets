## Session log — 30 June 2026 (Venus polish sprint: five fixes, no redesign)

Five small, isolated fixes from a live Venus playthrough. Nothing outside these five was touched.

**1. Streaming jump fixed.** `#va-glass` is `position:fixed; bottom:0;` and grows upward as paragraphs fade in. The old code reset `scrollTop=0` once on insertion, but every later paragraph/kybalion reveal still shifted the whole panel as it grew — that was the visible jump. `vaRenderCard()` now captures the new card's `offsetTop` once as an anchor and re-pins `va-glass.scrollTop` to that same anchor after every reveal step (each paragraph, the kybalion line). The text now stays put while it streams.

**2. Ending no longer asks a question right before the declarative close.** The closing card's line ("You already know what to do with this.") was already declarative — the contradiction was that Venus's own *final oracle reply*, generated by the API, always includes a `question` field per the system prompt, and that question rendered immediately above the closing card. `sendVenusNew()` now strips the `question` field from the JSON response on the exchange that triggers closing (the 2nd user message), so the visitor's last read from Venus is reflection, not a question, before the declarative close.

**3. CTA order fixed.** "Receive your first key" is the primary completion moment and was already first in DOM order, but `vaMaybeShowClosing()`'s reveal *timing* had it backwards — the Grimoire/Return row faded in at 6s and the key at 10s, so the secondary actions became visible and clickable before the key did. Reveal order is now line → separator → key (6s) → actions (9.2s), matching visual priority.

**4. Floating Venus artwork removed from the key reveal.** `#kr-key-img` (`Venus_Artwork.jpg`, large floating image) was competing with the key itself. Removed entirely per direction — the `✦` glyph (`#kr-key-fallback`) is now the sole visual in `#kr-key-wrap`, always shown rather than as an error fallback. `collectKey()`'s pulse-on-collect animation now targets the glyph; added `#kr-key-fallback.pulse` keyframe hookup. The old `#kr-key-img` CSS rule is now orphaned (harmless, left in place — not part of this sprint's scope).

**5. Grimoire "Return" now actually returns home.** `closeGrimoire()` previously only hid the overlay in place, leaving the visitor stranded on a finished Venus conversation with no clear next step (the only way out was the small global `#returnBtn`). For Venus/council contexts, Return now explicitly flashes back to the Foyer (`flashTo(() => { showScreen('foyer'); councilReset(); })`), matching the pattern Ganymede's ending already uses. Ganymede's in-cave behavior (Grimoire reachable mid-session) is unchanged — `closeGrimoire()` still short-circuits and stays in the cave when `currentScreen==='ganymedeScreen'`.

---

### Decisions locked in this sprint

**Venus's question field is suppressed, not removed from the schema.** `VSYS` still asks for a `question` on every turn — useful for normal back-and-forth exchanges. Only the specific reply that triggers the closing sequence has its question stripped client-side before rendering. This was the minimal-footprint fix; touching the system prompt itself was out of scope and would have affected every exchange, not just the last one.

**Artwork removal was a deliberate "key stays the hero" call**, not a placeholder gap — confirmed with El before implementing. If a future sprint wants a more considered key visual treatment (the BIBLE principle is "El's artwork is always present, always sacred, revealed at the emotional peak" — this specific moment was deemed *not* that peak; the artwork's emotional reveal already happens earlier, in the Venus video corridor), that's a new design decision, not a revert of this one.
